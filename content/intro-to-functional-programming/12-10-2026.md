# Lecture 4

Definining a monomorphic list of `ints`:

``` haskell
data ListInt where
  Empty :: ListInt
  Cons :: Int -> ListInt -> ListInt
```

We can now write, for example:
``` haskell
Empty :: ListInt
Cons 5 Empty :: ListInt
Cons 3 (Cons 5 Empty) :: ListInt

isEmpty :: ListInt -> Bool
isEmpty Empty = True
isEmpty (Cons x xs) = False
```

However, it would be better to have lists that work for any type. Therefore, lists are defined in the prelude like:

``` haskell
data [a] where -- where a is a polymorphic type
  [] :: [a]
  (:) :: a -> [a] -> [a]
```

`[3,4,5]` is syntactic sugar for `3 : 4 : 5 : []`
Therefore, to add something to the end, we have to traverse the entire list.

Anatomy of a list:
    `3 : 4 : 5 : []`
    (head) (tail)

So we have the following functions defined:
``` haskell
head :: [a] -> a
head (x:xs) = x

tail :: [a] -> [a]
tail (x:xs) = xs
```
...where `x` denotes the first element, and `xs` the remaining elements

These are dangerous because `head []` and `tail []` cause an error.

Instead:
``` haskell
isEmpty :: [a] -> Bool
isEmpty [] = True
isEmpty _ = False
```

Another definition:
``` haskell
isSingle :: [a] -> Bool
isSingle [x] = True
isSingle _ = False
```
Another dangerous function:
``` haskell
second :: [a] -> a
second [x,y] = y
second [x,y,z...]
```
We can use this but still dangerous:
``` haskell
second (x:y:zs) = y
```
But consider `[]` and `[x]`. 

Consider a function which adds all of a list's elements together:
``` haskell
sum :: [Int] -> Int
sum [] = 0
sum (x:xs) = x + sum xs
```

The length of a list:
``` haskell
length :: [a] -> Int
length [] = 0
length (x:xs) = 1 + length xs
```

The append function sticks two list together:
`[1,2,3] ++ [4,5,6] = [1,2,3,4,5,6]`

We define this using pattern matching:

``` haskell
(++) :: [a] -> [a] -> [a]
[] ++ ys -> ys
(x:xs) ++ ys  -> x : (xs ++ ys)
```
